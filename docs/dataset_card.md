# Қалқан-Corpus — карточка датасета

Корпус диалогов для обучения инкрементального детектора мошеннических звонков
на казахском и русском языках. Текущая версия — **v2** (темы не выдают класс);
что изменилось относительно v1 и почему — в разделе
[«История: артефакт темы в v1»](#история-артефакт-темы-в-v1).

## Кратко

| | |
|---|---|
| Диалогов | 3 400 train + 600 val + 1 000 holdout (разбиение по шаблонам); отдельно 4 000 со случайным разбиением (`corpus.jsonl`) |
| Реплик | ~32 600 на 4 000 диалогов |
| Языки | русский, казахский, смешанная речь (code-switching) |
| Классы | 11 мошеннических сценариев, 11 легитимных — 11 тематических пар |
| Разметка | на уровне реплики: стадия, красные флаги, язык, намерение; на уровне диалога — тема, момент целевого действия |
| Происхождение | синтетический, порождён из документированной таксономии |
| Лицензия | предполагается CC-BY-4.0 (публикуемый артефакт работы) |

## Как построен

Методика следует [TeleAntiFraud-28k](https://arxiv.org/html/2503.24115v2): корпус
порождается из документированных сценариев, а не из записей реальных разговоров.
Это снимает вопрос персональных данных и позволяет опубликовать датасет —
реальные записи звонков опубликовать было бы нельзя.

Источник сценариев — открытые предупреждения казахстанских ведомств:
Генпрокуратура РК, Национальный Банк РК, МВД РК, ЕНПФ, Минздрав РК, АФМ РК,
полиция. Ни один сценарий не выдуман: каждый привязан к публикации
(`data/taxonomy/scam_scenarios.yaml`, поле `sources`).

Конвейер: таксономия сценариев → **тема → класс → сценарий** → банк реплик
по стадиям (S0–S1 из общего пула темы) → генератор (слоты, профиль жертвы,
языковой профиль) → разметка красных флагов детектором по тексту.

### Темы и сценарии

У каждой темы — мошеннический сценарий и легитимный звонок на ту же тему:

| Тема | Мошенничество | Легитимный звонок |
|---|---|---|
| bank | SC01 служба безопасности → «безопасный счёт» | BN01 банк подтверждает операцию |
| credit | SC06 «одобренный кредит» + фишинговая ссылка | BN04 взыскание по реальной просрочке |
| telecom | SC02 продление договора на SIM → код из SMS | BN05 оператор предлагает тариф |
| telecom_security | SC03 SMS-бомбинг + «Антиспам» | BN09 настоящее уведомление о безопасности номера *(v2)* |
| pension | SC04 ЕНПФ: «неучтённый стаж» | BN10 информационный звонок ЕНПФ / ЦОН *(v2)* |
| invest | SC05 фейковые инвестиции | BN07 лицензированный брокер |
| tech_support | SC07 удалённый доступ (AnyDesk, демонстрация экрана) | BN11 техподдержка по заявке клиента *(v2)* |
| relative | SC08 клонированный голос родственника | BN02 родственник действительно просит денег |
| delivery | SC09 «курьер» просит код из SMS *(v2)* | BN03 настоящий курьер |
| clinic | SC10 «поликлиника»: «номер медицинской декларации» = код DamuMed *(v2)* | BN06 регистратура подтверждает запись |
| job | SC11 вакансия-приманка: вербовка дропперов *(v2)* | BN08 работодатель / HR |

```jsonc
  "action_turn_idx": 11,              // реплика с запросом целевого действия, -1 если нет
  "target_action": ["disclose_sms_code"],
  "split": "train",                   // train | val | holdout (corpus.jsonl: train | val | test)
  "turns": [

      "idx": 0,
      "speaker": "caller",            // caller | victim
      "text": "...",
      "stage": "S0",                  // S0..S6, SB

      "intent": "...",
      "red_flags": ["keep_line_open"],

    }

```

## Что сделано, чтобы задача не была фиктивной

Синтетический корпус легко сделать таким, что любая модель покажет на нём 0.99 —
и развалится на реальном звонке. Все проверки ниже автоматические
(`validate_corpus.py`, `check_separability.py`).

**1. Тема и приветствие не выдают класс (v2).** Диалог порождается
«тема → класс → сценарий», поэтому тема встречается в обоих классах одинаково
часто (44–53% мошенничества в каждой из 11 тем). Приветствие (S0) и
подтверждение личности (S1) берутся из общего пула темы для обоих классов —
как в жизни, где мошенник «из службы безопасности банка» здоровается теми же
словами, что и настоящий банк. Проверка: простейшая модель (логистическая
регрессия на символьных n-граммах), обученная на первой реплике train, на
шаблонном holdout даёт **AUC 0.501** (первые три реплики — 0.513). Классы
расходятся со стадии S2 — там, где начинается манипуляция: та же модель по
всему диалогу даёт 0.896.

**2. Длина диалога не выдаёт класс.** 38% мошеннических диалогов обрываются
жертвой до запроса целевого действия. Медианная длина обоих классов — 8 реплик.

**3. Красные флаги встречаются в обоих классах.** 12 из 20 срабатывающих флагов
присутствуют и в легитимных звонках: настоящий банк тоже торопит, настоящий брат
тоже просит не говорить маме, настоящая техподдержка тоже говорит «не кладите
трубку» и предлагает демонстрацию экрана в своём приложении. 28,8% легитимных
диалогов содержат хотя бы один флаг; 29,7% мошеннических не содержат ни одного.
Только в мошенническом классе остаются 8 флагов («безопасный счёт», AnyDesk,
код из SMS, гарантированный доход, передача «следователю», ссылка, плата за
вывод, эмоциональная срочность) — в легитимном звонке они действительно не звучат.

**4. Разбиение по шаблонам — на три части.** train, val и holdout собраны из
разных формулировок. Holdout отвечает на вопрос, понимает ли модель приём
манипуляции или запомнила фразы; val (v2) — на нём выбирается порог. Реплики
звонящего на стадиях S2+ на русском пересекаются с обучением на 0,8% (holdout).

## Rule-based бейзлайн

Регулярные выражения по каталогу красных флагов с накопительным риском —
то, что банк может собрать за день.

**На шаблонном holdout v2** (`results/baseline_rules_holdout.json`) — точка
отсчёта для обученной модели:

| Порог | Precision | Recall | F1 | FPR | Медиана запаса до целевого действия | Успели заранее |
|---|---|---|---|---|---|---|
| 0.60 | 0.718 | 0.590 | 0.648 | 0.232 | 2 реплики | 58% |
| 0.70 | 0.810 | 0.588 | 0.681 | 0.138 | 2 реплики | 58% |
| 0.80 | 0.830 | 0.518 | 0.638 | 0.106 | 0 реплик | 48% |
| 0.90 | 1.000 | 0.336 | 0.503 | 0.000 | 0 реплик | 14% |

ROC AUC правил на holdout — 0.724. На случайном test-сплите `corpus.jsonl`
(шаблоны пересекаются с обучением; `results/baseline_rules.json`) при пороге 0.6:
precision 0.721, recall 0.659, F1 0.688, FPR 0.239.

Правила либо поднимают ложную тревогу почти на каждом четвёртом легитимном
звонке, либо пропускают две трети мошенничества и почти никогда не успевают
предупредить заранее.

## Внешний тест на реальных звонках

Переносится ли детектор с синтетики на живую речь. Источники, лицензии
и конвейер — [data/external/README.md](../data/external/README.md).
Внутри каждого набора оба класса прошли один конвейер (ASR, нарезка, перевод).

| Набор | Что внутри | n (scam/benign) | ROC AUC правил | Recall @0.6 | FPR @0.6 | Хоть один флаг: scam / benign |
|---|---|---|---|---|---|---|
| holdout v2 (синтетика) | шаблонный holdout | 500 / 500 | 0.724 | 0.590 | 0.232 | 60% / 26% |
| `korccvi_ru` | реальный вишинг (Корея, FSS) vs обычные звонки; ko→ru | 200 / 200 | 0.505 | 0.010 | 0.000 | 1% / 0% |
| `en_bank_ru` | реальные скам-звонки (YouTube) vs звонки в банк; en→ru | 211 / 211 | 0.505 | 0.009 | 0.000 | 1% / 0% |
| `en_topic_ru` | те же скам-звонки vs легитимные на ту же тему; en→ru | 98 / 98 | 0.505 | 0.020 | 0.010 | 2% / 1% |
| `kazllm_kk` | реальные звонки (korccvi + en_bank) → казахский, KazLLM | 40 / 40 | 0.512 | 0.000 | 0.000 | 3% / 0% |
| `youtube_kz` | реальные звонки мошенников казахстанцам, русская речь, Whisper | 4 / 0 | — | 0 из 4 | — | 0 из 4 |
| контроль: ko/en без перевода | правила обязаны молчать | | 0.50 | ≈0 | 0 | ≈0 |

**Rule-baseline на реальной речи не работает вообще** (AUC ≈ 0.5). Это не
артефакт перевода: мошеннический смысл в переведённых текстах есть
(в `korccvi_ru` «прокуратура/полиция/следствие» — 56% мошеннических звонков
против 8% легитимных, «мошенничество/преступление» — 50% против 3%;
в `en_bank_ru` «компьютер/вирус/взлом» — 58% против 0%), но регулярные выражения
описывают формулировки наших шаблонов, а не приём манипуляции. Пример из
`youtube_kz`: мошенник говорит «Удалённый рабочий стол… это антивирусная
программа, и жмите установить» — флаг `remote_access_request` не срабатывает.
Обратный эффект: в легитимных звонках банка «код/пароль» (33%) и «счёт/карта»
(69%) звучат чаще, чем в мошеннических, — словарь давал бы ложные тревоги.

## Обученный детектор (XLM-R + LoRA, корпус v2)

Модель: `xlm-roberta-base` + LoRA (r=16, 1,48 млн обучаемых параметров из 280 млн),
после каждой реплики — вероятность мошенничества по всему префиксу разговора,
накопитель риска и порог выбраны на val (FPR ≤ 5%). Обучение — Kaggle T4, 3 сида;
оценка на реальных звонках — локально (`src/eval_detector.py`,
`results/detector_summary.md`).

**Реальные звонки (ROC AUC, среднее ± разброс по 3 сидам):**

| Набор | Модель | Правила |
|---|---|---|
| реальный вишинг, Корея → ru | **0.751 ± 0.032** | 0.505 |
| реальные скам-звонки против звонков в банк, en → ru | **0.733 ± 0.052** | 0.505 |
| реальные скам-звонки против легитимных на ту же тему, en → ru | 0.598 ± 0.026 | 0.505 |
| те же реальные звонки → kk (KazLLM) | **0.709 ± 0.057** | 0.512 |
| звонки мошенников казахстанцам (n = 4, только recall) | тревога в 11 из 12 прогонов | 0 из 4 |

Модель, обученная только на синтетике, ранжирует реальные мошеннические звонки
выше легитимных на трёх независимых источниках; правила там на уровне монетки.
На модели v1 набор «против звонков в банк» давал 0.412 — исправление корпуса
(темы) подняло его до 0.733.

**Шаблонный holdout при одинаковом FPR** (доля тревог, прозвучавших ДО запроса
SMS-кода / перевода / установки программы):

| FPR | Recall правил | Recall модели | Заранее: правила | Заранее: модель |
|---|---|---|---|---|
| 10% | 0.388 | 0.392 | 37% | **94%** |
| 23% | 0.590 | 0.538 | 58% | **91%** |

Правила срабатывают на самой просьбе «продиктуйте код» — когда уже поздно;
модель ловит манипуляцию на стадиях S2–S3. По первой реплике модель класс
не определяет (AUC 0.48–0.51).

**Где модель проигрывает — честно:**

- ROC AUC на шаблонном holdout ниже, чем у правил (0.674 против 0.724). Но
  holdout не отложен для правил: регулярные выражения писались по всему
  фразобанку, включая формулировки holdout. На реальных звонках такой форы нет.
- Порог, выбранный на синтетической валидации, на реальные звонки не
  переносится: при нём FPR 0.40–0.74. Модель хорошо ранжирует, но
  вероятности не откалиброваны под реальное распределение — в развёртывании
  порог должен подбирать каждый банк на своих звонках.
- Реальные пары «на одну тему» разделяются слабо (0.598) — это самый честный
  и самый трудный тест, и здесь модели есть куда расти (расширение фразобанка).

## История: артефакт темы в v1

Обученная на корпусе v1 модель (XLM-R + LoRA) на шаблонном holdout дала
ROC AUC 0.96–0.98 — и почти всё решала **по первой реплике** (AUC только по
приветствию 0.972). Причины:

- тема выдавала класс: ЕНПФ, «Антиспам», AnyDesk встречались только
  у мошенников, курьер, поликлиника и HR — только у легитимных;
- приветствия внутри пар одной темы были написаны разным стилем (у мошенника —
  «алаяқтыққа қарсы бөлім», у банка — «служба мониторинга»), и даже простейшая
  модель на символьных n-граммах по первой реплике давала AUC 0.911;
- валидация собиралась из тех же шаблонов, что обучение, — модель была уверена
  на 100%, порог уходил в ≈ 0, на новых формулировках FPR 0.30–0.37.

На реальных звонках это проявилось сразу: модель выучила «звонок про банк =
мошенничество», и **настоящее приветствие банка получало p ≈ 1.0** — на наборе
«реальные скам-звонки против звонков в банк» AUC 0.412, хуже случайного.
При этом на реальном вишинге (0.774) и казахском переводе (0.755) модель уже
тогда была заметно лучше правил (0.50) — то есть сигнал есть, но смешан с темой.

`check_separability.py` проверял только флаги и этого не видел. В v2 добавлены
проверки темы и «начала разговора», и корпус перестроен (`topics.yaml`).
Результаты v1 сохранены в `results/v1_corpus/`.

## Ограничения — честно

**Корпус синтетический.** Он воспроизводит документированные схемы, но не
живую речь: реальные звонки содержат перебивания, оговорки, фоновый шум,
незаконченные фразы. Внешний тест показал, что правила, настроенные на корпус,
на реальной речи не срабатывают.

**Реальных казахоязычных записей мошеннических звонков в открытом доступе нет.**
Полиция и банки РК публикуют текстовые предупреждения, а не аудио; на YouTube —
единичные ролики, в основном на русском. Казахский внешний тест — это перевод
реальных звонков (KazLLM), а не живая казахская речь.

**ASR для казахского искажает ключевые слова.** Whisper large-v3 записал
«ешкімге айтпаңыз» как «еш кім ғайтпаңыз», «зейнеткер» — как «зенеткер».
Детектор в проде будет получать именно такой текст; для казахского нужен
специализированный ASR (напр., модели ISSAI) и устойчивость к его ошибкам.

**Фразобанк мал, особенно казахский.** У многих пулов 2–3 варианта, поэтому
три части разбиения по шаблонам делятся не полностью: реплики val на 35%
(русские реплики звонящего S2+) и на 88% (казахские) собраны из шаблонов,
встречавшихся в обучении; в holdout — 0,8% и 22,5%. Порог, выбранный на val,
поэтому всё ещё оптимистичен. Нужно расширение формулировок, прежде всего
казахских.

**Казахский текст нуждается в вычитке носителем.** Формулировки порождены
без участия носителя языка и могут содержать неестественные обороты.
Казахские паттерны `redflags.py` тоже беднее русских (часть казахских реплик
с маркером флаг не ловит).

**Реплики жертвы не всегда точно отвечают на реплику звонящего.** Ответы
выбираются по стадии, а не по содержанию предыдущей фразы.

**Во внешних данных нет разметки стадий**, поэтому «успели до целевого действия»
на них не считается — только позиция первой тревоги.

**Сценарий SC08 (клонированный голос) по тексту принципиально плохо отделим**
от BN02 (реальная просьба родственника): различие лежит в акустике. Текстовая
модель здесь ограничена сверху.

## Воспроизведение

```bash
cd src
python generate_corpus.py --n 4000         # corpus.jsonl (случайное разбиение)
python make_template_holdout.py            # corpus_train.jsonl (train/val) + corpus_holdout.jsonl
python validate_corpus.py                  # длина, обрывы, покрытие
python check_separability.py               # флаги, темы, «начало разговора»
python run_baseline.py --corpus ../data/generated/corpus_holdout.jsonl --split holdout --out ../results/baseline_rules_holdout.json

# внешний тест (сырые данные — см. data/external/README.md)
python prepare_external.py
python translate_external.py --tgt ru
python translate_kazllm.py --per-class 20 --max-turns 15
python transcribe_youtube.py
python run_external_baseline.py
```
