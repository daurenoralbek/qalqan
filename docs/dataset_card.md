# Қалқан-Corpus — карточка датасета

Корпус диалогов для обучения инкрементального детектора мошеннических звонков
на казахском и русском языках.

## Кратко

| | |
|---|---|
| Диалогов | 4 000 (обучение) + 1 000 (отложенный набор) |
| Реплик | ~31 000 |
| Языки | русский, казахский, смешанная речь (code-switching) |
| Классы | 8 мошеннических сценариев, 8 легитимных |
| Разметка | на уровне реплики: стадия, красные флаги, язык, намерение |
| Происхождение | синтетический, порождён из документированной таксономии |
| Лицензия | предполагается CC-BY-4.0 (публикуемый артефакт работы) |

## Как построен

Методика следует [TeleAntiFraud-28k](https://arxiv.org/html/2503.24115v2): корпус
порождается из документированных сценариев, а не из записей реальных разговоров.
Это снимает вопрос персональных данных и позволяет опубликовать датасет —
реальные записи звонков опубликовать было бы нельзя.

Источник сценариев — открытые предупреждения казахстанских ведомств:
Генпрокуратура РК, Национальный Банк РК, МВД РК, ЕНПФ, полиция области Абай.
Ни один сценарий не выдуман: каждый привязан к публикации ведомства.

Конвейер: таксономия сценариев → банк реплик по стадиям → генератор
(слоты, профиль жертвы, языковой профиль) → разметка красных флагов
детектором по тексту.

## Что сделано, чтобы задача не была фиктивной

Синтетический корпус легко сделать таким, что любая модель покажет на нём 0.99 —
и развалится на реальном звонке. Три меры против этого:

**1. Длина диалога не выдаёт класс.** 42% мошеннических диалогов обрываются
жертвой до запроса целевого действия. Медианная длина обоих классов — 8 реплик,
диапазоны пересекаются на 55%.

**2. Красные флаги встречаются в обоих классах.** 7 из 19 срабатывающих в корпусе
флагов присутствуют и в легитимных звонках: настоящий банк тоже торопит, настоящий
брат тоже просит не говорить маме, настоящий оператор тоже грозит отключением услуги.
(По тексту детектируются 20 флагов из 23 в таксономии; `time_pressure` в корпусе
не срабатывает ни разу — его паттерны не покрывают формулировки фразобанка.)
21,6% легитимных диалогов содержат хотя бы один флаг; 27,2% мошеннических
не содержат ни одного. Модель не может решить задачу по словарю.

**3. Отложенный набор по шаблонам.** Тестовые диалоги собраны из формулировок,
которых не было в обучении. Это отвечает на вопрос, поняла ли модель приём
манипуляции или запомнила фразы.

## Rule-based бейзлайн

Регулярные выражения по каталогу красных флагов с накопительным риском —
то, что банк может собрать за день.

**На шаблонном holdout** (`corpus_holdout.jsonl`, 1000 диалогов, формулировки
не встречались в обучении) — это точка отсчёта для обученной модели
(`results/baseline_rules_holdout.json`):

| Порог | Precision | Recall | F1 | FPR | Медиана запаса до целевого действия | Успели заранее |
|---|---|---|---|---|---|---|
| 0.60 | 0.745 | 0.700 | 0.722 | 0.240 | 3 реплики | 73% |
| 0.70 | 0.738 | 0.676 | 0.706 | 0.240 | 2 реплики | 67% |
| 0.80 | 0.770 | 0.638 | 0.698 | 0.190 | 2 реплики | 52% |
| 0.90 | 1.000 | 0.394 | 0.565 | 0.000 | 0 реплик | 0% |

Для справки, на случайном test-сплите `corpus.jsonl` (600 диалогов, шаблоны
пересекаются с обучением; `results/baseline_rules.json`): при пороге 0.6 —
precision 0.793, recall 0.723, F1 0.756, FPR 0.198. Сравнивать модель нужно
с цифрами на holdout.

Это и есть проблема, которую решает обучаемая модель: правила либо поднимают
ложную тревогу на каждом пятом легитимном звонке, либо пропускают две трети
мошенничества и почти никогда не успевают предупредить заранее.

## Внешний тест на реальных звонках

Проверка до обучения модели: переносится ли детектор с синтетики на живую речь.
Источники, лицензии и конвейер — [data/external/README.md](../data/external/README.md).
Внутри каждого набора оба класса прошли один конвейер (ASR, нарезка, перевод).

| Набор | Что внутри | n (scam/benign) | ROC AUC | Recall @0.6 | FPR @0.6 | Хоть один флаг: scam / benign |
|---|---|---|---|---|---|---|
| holdout (синтетика) | шаблонный holdout | 500 / 500 | 0.783 | 0.700 | 0.240 | 70% / 24% |
| `korccvi_ru` | реальный вишинг (Корея, FSS) vs обычные звонки; ko→ru | 200 / 200 | 0.505 | 0.010 | 0.000 | 1% / 0% |
| `en_bank_ru` | реальные скам-звонки (YouTube) vs звонки в банк; en→ru | 211 / 211 | 0.505 | 0.009 | 0.000 | 1% / 0% |
| `en_topic_ru` | те же скам-звонки vs легитимные на ту же тему; en→ru | 98 / 98 | 0.505 | 0.020 | 0.010 | 2% / 1% |
| `youtube_kz` | реальные звонки мошенников казахстанцам, русская речь, Whisper | 4 / 0 | — | 0 из 4 | — | 0 из 4 |
| контроль: ko/en без перевода | правила обязаны молчать | | 0.50 | ≈0 | 0 | ≈0 |

**Вывод: rule-baseline на реальной речи не работает вообще** (AUC ≈ 0.5 — уровень
монетки). Это не артефакт перевода: мошеннический смысл в переведённых текстах есть
(в `korccvi_ru` «прокуратура/полиция/следствие» — 56% мошеннических звонков против 8%
легитимных, «мошенничество/преступление» — 50% против 3%; в `en_bank_ru`
«компьютер/вирус/взлом» — 58% против 0%), но регулярные выражения описывают
формулировки наших шаблонов, а не приём манипуляции. Пример из `youtube_kz`:
мошенник говорит «Удалённый рабочий стол… это антивирусная программа, и жмите
установить» — флаг `remote_access_request` не срабатывает. Обратный эффект тоже
есть: в легитимных звонках банка «код/пароль» (33%) и «счёт/карта» (69%) звучат
чаще, чем в мошеннических, — словарь ключевых слов давал бы там ложные тревоги.

Что это значит для обучаемой модели: **синтетический holdout не гарантирует
переноса.** Модель обязана оцениваться на этих внешних наборах; если она, как
и правила, выучит словарь шаблонов, это будет видно сразу.

## Ограничения — честно

**Корпус синтетический.** Он воспроизводит документированные схемы, но не
живую речь: реальные звонки содержат перебивания, оговорки, фоновый шум,
незаконченные фразы. Внешний тест (выше) показал, что правила, настроенные
на корпус, на реальной речи не срабатывают.

**Реальных казахоязычных записей мошеннических звонков в открытом доступе нет.**
Полиция и банки РК публикуют текстовые предупреждения, а не аудио; на YouTube —
единичные ролики, в основном на русском. Казахский внешний тест — это перевод
реальных звонков (KazLLM), а не живая казахская речь.

**ASR для казахского искажает ключевые слова.** Whisper large-v3 записал
«ешкімге айтпаңыз» как «еш кім ғайтпаңыз», «зейнеткер» — как «зенеткер».
Детектор в проде будет получать именно такой текст; для казахского нужен
специализированный ASR (напр., модели ISSAI) и устойчивость к его ошибкам.

**Во внешних данных нет разметки стадий**, поэтому «успели до целевого действия»
на них не считается — только позиция первой тревоги.

**Казахские пулы беднее русских.** Из-за этого отложенный набор для казахского
слабее: 23,5% реплик в нём собраны из шаблонов, встречавшихся в обучении
(в основном короткие реплики вроде «Иә, тыңдап тұрмын»). Требуется расширение
казахских формулировок.

**Казахский текст нуждается в вычитке носителем.** Формулировки порождены
без участия носителя языка и могут содержать неестественные обороты.

**Реплики жертвы не всегда точно отвечают на реплику звонящего.** Ответы
выбираются по стадии, а не по содержанию предыдущей фразы, поэтому
встречаются смысловые рассогласования.

**Сценарий SC08 (клонированный голос) по тексту принципиально плохо отделим**
от BN02 (реальная просьба родственника). Это не дефект корпуса, а свойство
задачи: различие лежит в акустике, а не в словах. Текстовая модель здесь
ограничена сверху, и это надо измерять отдельно.

## Воспроизведение

```bash
cd src
python generate_corpus.py --n 4000         # основной корпус
python make_template_holdout.py            # разбиение по шаблонам
python validate_corpus.py                  # проверка на артефакты
python check_separability.py               # проверка нетривиальности
python run_baseline.py --corpus ../data/generated/corpus_holdout.jsonl     --split holdout --out ../results/baseline_rules_holdout.json   # бейзлайн на holdout

# внешний тест (сырые данные — см. data/external/README.md)
python prepare_external.py
python translate_external.py --tgt ru
python transcribe_youtube.py
python run_external_baseline.py
```
